# 設計の判断と理由

デッドアワーを作るときに、何を選び、何を捨てたか、その理由をまとめたものです。

## 画面の呼び方

この文書では、画面を次の名前で呼びます。

| 画面 | URL | 内容 |
|---|---|---|
| トップ | `/` | はじめる、続きから |
| 隊員登録 | `/setup` | 名前、毎日の時刻、拠点（家）の位置を登録する |
| 拠点 | `/home/{user_id}` | 拠点の3D、ゾンビとの距離、毎日の逃走、フリーラン、フリーズ |
| シェルター選び | `/reserve/{user_id}` | 毎日の逃走で逃げ込む公園とモードを選んで予約する |
| フリーランの公園選び | `/run/{user_id}` | 今いる場所の近くの公園とモードを選んで、すぐ走り出す |
| ゾンビ接近中 | `/escape` | 出発時刻までのカウントダウンと「脱出！」ボタン |
| 逃走中の地図 | `/escape` | 脱出した後の3Dの地図。シェルターまで逃げる |
| クリア／ゲームオーバー | `/escape` | 結果 |

## FastAPI + HTML/JS（捨てた案: Streamlit）

- 良い点: 現在地、カウントダウン、演出をブラウザの機能で自由に作れる。画面と裏の処理を分けて、2人で分担しやすい
- 悪い点: JavaScript が必要になり、Streamlit より画面を作る手間が増える

## ゾンビは時刻に合わせて家へ近づき、家を出たら追いかける

- 毎日の時刻にちょうど家へ着く速さで近づく
- シェルターを選ばずに時刻が来たらゲームオーバー。選ばないまま外にいても追跡は始まらない
- 時刻が来たときに追跡が始まっていなければ（家から動いていなければ）ゲームオーバー
- 「脱出！」を押すか、家から200m以上離れた位置が届くと、モードの速さの追跡に切り替わる
- 「脱出！」は家にいても押せる。押した瞬間に追跡が始まるので、家にとどまれば追いつかれる。以前は家から200m離れないと押せず、それまで道の線が出なかったので、どちらへ進むか分からなかった
- クリアすると追跡を終え、ゾンビは5km先に出直す。次は翌日の時刻に来る
- 閉じている間は位置が届かないので、外出していても家にいる扱いになる
- シェルターは家の周りから予約するが、時刻に外出先（家から1.5km以上）で脱出し、予約したシェルターが遠すぎるときは、今いる場所の近くで、予約したときと同じくらいの距離のシェルターに替える

## ゾンビの追跡の位置はサーバーで計算（捨てた案: バックグラウンドGPS、ネイティブアプリ）

- 良い点: 閉じている間も、基準の位置と経過時間から正しい位置を計算できる。常時GPSがなく、バッテリーや位置情報の負担が小さい
- 悪い点: 閉じている間に移動しても、ゾンビは最後に開いた場所へ向かう。Webは画面が消えると現在地の更新が止まることがあるので、逃げ切りの判定はチェックインで行う
- ゾンビは道路を無視して直進する

## 通知: FCM + Cloud Scheduler（捨てた案: カレンダーとの併用）

- 「あと1km」のような状況に応じた通知を送る。5分ごとに距離を確認し、3km、1km、300mの段階を超えたら1回だけ送る。毎日の時刻の10分前（脱出できるようになる時刻）と、捕まったときにも送る
- 5分ごとにしたのは、10分前の知らせを遅れずに届けるため。15分ごとだと、知らせが時刻を過ぎてから届くことがある
- iPhone はホーム画面に追加したときだけ通知を受け取れる（Webプッシュの制約）。ホーム画面のアプリは別の端末として扱われることがあるので、先に引き継ぎコードを入れてから通知をオンにする。**実機では未検証**
- 22時から7時は距離と捕獲の通知を送らない。10分前の知らせは本人が決めた時刻のものなので、深夜でも送る
- カレンダー（.ics）で時刻を知らせる案は捨てた。画面のボタンが増えて分かりにくく、動きもカレンダーアプリに依存するため


## 地図: Maps JavaScript API（捨てた案: 距離のゲージだけ）

- 良い点: ゾンビとの位置関係が一目で分かる。現実の街をそのままゲームの舞台にできる
- 悪い点: ブラウザからキーが見えるので、サイトの制限が必須。歩きながら画面を見ると危ないので、音と振動を中心にする
- 読み込めないときは簡易レーダーに切り替える
- 逃走中の地図だけ、傾けたベクター地図にする。傾きと回転はベクター形式のマップIDでだけ効き、使えない環境では平らな地図のまま動く

## 拠点は地図と切り離した3D（捨てた案: 実際の地図の家の位置に拠点を置く）

- 良い点: 家の座標を画面に渡さずに済む。拠点の画面で地図を読み込まないので、Maps の利用料も増えない
- 悪い点: 自分の家の上に拠点が建つ臨場感はない
- 外に出たら（逃走中の地図）実際の地図に切り替わる

## 3D: three.js を自前で配信（捨てた案: 実写の3D地図、3Dモデルの素材集、CDNからの読み込み）

- 拠点のジオラマと、逃走中の地図に重ねる人物とゾンビを three.js で描く。逃走中の地図では Maps JavaScript API の WebGLOverlayView の上に載せる
- 実写の3D地図は、スマホでは重く、読み込みごとの課金も高い。デフォルメした傾けた地図のほうが位置情報ゲームらしく見える
- モデルは基本図形の組み合わせで自作した。素材集を使わないので、ライセンスの確認が three.js（MIT）だけで済む
- three.js 0.187.0 を `static/vendor/three/` に置き、gzip で送る（約1.5MB → 約290KB）。CDNに頼ると、デモ中の通信状況で読み込みに失敗する危険がある
- WebGL が使えない端末では、拠点は絵文字、逃走中の地図は2Dのマーカーに切り替わる

## 拠点ランクに一本化（捨てた案: 経験値とレベル）

- 経験値とレベルは捕まっても減らなかった。「失う怖さ」がないと、外に出る強制力にならない
- 拠点ポイント（逃げた距離＋ハードの上乗せ＋資材）の累計で拠点が10段階に豪華になり、捕まると（時刻に家から動いていない、追いつかれた）テントに戻る
- 段階の必要ポイントは、最初は上がりやすく、だんだん増やす（1,000／3,000／7,000／13,000／23,000／40,000／65,000／100,000／155,000）。毎日1回ノーマルで中くらいの距離のシェルターへ逃げると、2日で小屋、2週間で要塞、3か月ほどで10段階目になる
- 毎日の時刻を過ぎたら、画面を閉じていると家を出たかどうか分からないので、家にいたものとして拠点は崩壊する
- シェルターの探索範囲も拠点ランクで広がる。成長の軸が1つになり、画面が分かりやすくなる
- 生涯の歩いた距離は減らさず、成果画面に出す

## 毎日の時刻は固定（捨てた案: シェルター選びで今回だけ時刻を変える）

- 以前はシェルター選びで、今回だけゾンビの来る時刻を変えられた
- 都合の悪い日に時刻をずらせると、毎日決まった時刻に外へ出る習慣にならない。このアプリの目的は「強制力で運動不足を解消する」こと
- シェルター選びでは時刻を選べない。予約は、次に来る毎日の時刻に向けたものになる
- 生活リズムが変わった人のために、毎日の時刻は拠点の画面で変えられる。ただし反映は翌日から。今日の到着がまだなら今日はもとの時刻のままで、直前に変えて逃れることはできない
- 到着を1回終えたら、次は必ず翌日以降。時刻を変えても1日に2回は来ない
- ぎりぎりに登録した人は、ゾンビをフリーランと同じ400m先に出し、時速6kmで来させる（4分後に着く。2回目からは毎日の時刻）。登録した直後のゲームオーバーを防ぎつつ、その日のうちに体験できるようにするため。翌日に回すと、登録した日に何も起きない

## ノーマルとハード（予約のたびに選ぶ）

- 徒歩は時速5km前後。一度はノーマルを時速4km（歩けば逃げ切れる）にしたが、試すと「10秒に10m」しか迫らず遅すぎて、追われる緊張感がなかった
- ノーマル: ゾンビ1体、時速6km。普通に歩くとじわじわ追いつかれ、早歩きで逃げ切れる
- ハード: ゾンビ3体、時速9km。走らないと逃げ切れない。追加の2体は本体と同じ方面（フリーランならシェルターと反対側）から、本体の左右少し後ろに群れで迫る。拠点ポイントは1.5倍（生涯の歩いた距離は実際の距離のまま）
- ハードのゾンビは見た目も変える。骨ばった体で前のめりに走り、片腕が取れかけている。100m以内に近づかれると、心臓の鼓動が速くなり、息づかいと叫び声が混ざり、画面のふちが赤く脈打つ
- その日の体調で選べるよう、登録時に固定せず、予約のたびに選ぶ
- 家へ近づく段階は時刻にちょうど着く動きなので、モードが効くのは追いかけてくる段階だけ

## フリーランを追加

- 毎日の時刻だけだと1日1回しか走れず、たくさん走りたい人に不親切だった
- 拠点の「フリーラン」から、いつでも何回でも走れる（Places の利用料が膨らまないよう、1日20回まで）。今いる場所の近くの公園を選び、ゾンビは背後400mから追ってくる
- 毎日の時刻より前なら、捕まっても拠点は崩壊させない。自分から走りに出た人を罰すると、気軽に走らなくなるため。その回のポイントが入らないだけ
- 毎日の時刻のゾンビはフリーランをしても必ず来る（習慣化の強制力は残す）。ただし毎日の時刻をまたいでシェルターまで逃げ切れば、その日の分は達成扱い
- 毎日の時刻より前に終わったフリーランでは、毎日のゾンビの距離を戻さない。走っている間も進んでいたものとして、続きから近づく。以前は走り終えるたびに5km先に戻って時刻に合わせて速くなり、だんだん迫ってくる感じが途切れていた
- 毎日の時刻をまたいで捕まると、拠点は崩壊する。以前は無傷だったので、時刻の直前に家でフリーランを押して放置するだけで、毎日のゾンビを逃れられた
- フリーラン中は毎日の脱出を押せない。逃走中のミッションが2つになると、片方が捕まっても残り続けて進行不能になるため
- 開始時の位置の精度は問わない。PC からでも3Dの世界に入って確かめられるようにするため。歩いた距離とアイテムは精度の良い位置でだけ数える

## アバターは three.js で自作（捨てた案: Blender で作る、無料の3Dキャラクター素材）

- 頭、胴、腕、脚を関節ごとに分けた人型を、基本図形で作った。速さに応じて、止まる（呼吸、きょろきょろ）、歩く、走る（大きく振る、前傾）を切り替える
- 服と肌の色を選べる。拠点のジオラマと、逃走中の地図の両方に出る
- 外部ツールも素材のライセンス確認も要らず、ゾンビや拠点と見た目がそろう

## 逃走中の地図は位置情報ゲームのような視点

- ズーム19、最大の傾き（67.5度）。カメラの向きの少し先を画面の中心にして、自分を中央よりやや下に置く
- アバター、ゾンビ、アイテムは実寸だと小さすぎるので大きく描く。大きさは地図の上で固定し、地図と一緒に拡大・縮小する（画面上で一定にすると、縮小したときに街より巨大に見えた）。引きすぎて見失わないよう、開いたときの見た目の4分の1より小さくはしない
- 自分の位置は GPS の更新の間を補間して、なめらかに動かす
- カメラは歩く向きで自動では回さない。1本指の左右で自分の周りを回り、上下で傾く。2本指で拡大と回転をする。標準の操作（2本指で傾ける、Ctrl を押してドラッグ）は気づかれにくく、真上からしか見られていなかった。指で動かしても追従は止めない。「真上から見る」のボタンも置く。Google マップの傾きは最大67.5度なので、真横にはできない
- 画面の外にいるゾンビは、画面の端に方角と距離の矢印で示す
- マップIDがベクター形式でないと3Dが出ない。そのときは画面に知らせる

## 公園選びに地図と住所を出す

- 公園の名前だけでは場所が分かりにくかったので、シェルター選びとフリーランの公園選びに、候補の公園の地図と短い住所を出す
- 地図には公園だけを番号付きのピンで出し、家（今いる場所）の印は出さない。地図の範囲も公園だけに合わせ、真ん中が家にならないようにする
- 住所は Places API の短い住所（shortFormattedAddress）を使う

## アイテム: 資材（捨てた案: 撃退アイテム）

- 一時は、ゾンビ全員を300m遠ざける「撃退」アイテムを置いていた。逃げる時間が延びるだけで、追われる緊張感が薄れるのでやめた
- 「資材」は拠点ポイント+200。シェルターに着いたときに入り、途中で捕まると失う
- 置き場所: 脱出した地点からシェルターへの直線上に、約300mおきに1〜3個。左右に最大30mずらす。家から200m以内には置かない（家の位置を推測させないため）
- 拾い方: 40m以内に入ると自動で拾い、振動で知らせる。歩きながら画面をタップさせないため
- 割り切り: 直線上に置くので、川や建物の中に落ちることがある。回収の半径で多くは吸収できる

## フリーズ（ゾンビを1日止める）

- 毎日の逃走の道に、2〜3回に1回フリーズが落ちている。シェルターまで持ち帰ると1つたまる（最大3）
- 拠点で使うと、次の毎日の時刻にゾンビが来ない。休んだ日も連続日数は切れない（数は増えない）
- 毎日続けるのがきつい日の逃げ道。自分で使う日を選べるようにした
- フリーランでは落ちない。何回でも走れるので、集めて毎日の時刻を飛ばし続けられてしまう

## 歩いた距離は画面で数え、サーバーで範囲に収める（捨てた案: サーバーで位置から数える、歩数）

- 保存する位置は丸めているので、サーバーでは道のりを足し合わせられない
- 画面は、精度30m以内の位置どうしの距離を足し、時速15kmを超える区間（乗り物）を除く。開き直しても続きから数えられるよう端末に残す
- サーバーは、直線距離を下限、「出発10分前から時速15kmで歩き続けた距離」を上限にして計上する。画面を閉じて歩いた人にも直線距離は認め、値の書き換えや乗り物は時間で頭打ちにする
- 歩数は、Webアプリからスマホの歩数計を読めないため出さない

## Firestore（捨てた案: Cloud SQL）

- 良い点: 常時起動のサーバーが要らず、少ないクレジットで動かしやすい。トランザクションで拠点ポイントの二重加算を防げる
- 悪い点: 複雑な集計は苦手。利用データの分析には工夫が要る

## 徒歩ルートはアプリの地図に出す（捨てた案: Googleマップへのリンク）

- 逃走中の地図で Routes API から徒歩ルートを取り、地図に線で引く。画面を切り替えずに進む道が分かる
- 費用がかかるので、逃走中の地図を開いたときと「ルートを更新」のときだけ呼ぶ。同じ場所からは10分キャッシュする
- 脱出した後だけ受け付け、出発地点は保存しない。家で脱出すれば家からのルートを Routes API に送ることになるが、保存はせず、家の周りの地図もすでに Maps で読み込んでいるので許容した

## 音: BGM と効果音をブラウザで鳴らす（捨てた案: 音楽ファイル、生成AIの曲）

- 逃走中の地図で、Web Audio で組み立てた不気味なBGMを鳴らす。心臓の鼓動、ゾンビのうめき声、足を引きずる音などを合成する。音楽ファイルを置かないので、著作権の確認も配信の費用も要らない
- 音で状況が分かるようにする。ハードで近づかれると鼓動が速くなり、捕まったときは効果音が鳴る。歩きながら画面を見なくて済む
- スマホは画面に触るまで音を出せないので、「脱出！」や画面への最初のタップで鳴らし始める。画面を消すと止まる
- 自分の音楽を聴きながら走る人もいるので、オン・オフを切り替えられる（端末ごとに覚える）

## 端末に結びつける（捨てた案: URLだけを鍵にする、Googleログイン、公園の距離を丸める）

- URLは画面共有、履歴、ログに残りやすい。以前はURLを知っていれば他人でも拠点を開けて、公園の一覧から家の近所まで分かった
- 登録した端末に鍵（HttpOnly の Cookie）を渡し、ハッシュだけを保存する。鍵が一致しない端末では、拠点もAPIも開けない。ミッションのURLも同じ
- 別の端末へは、拠点で発行する引き継ぎコードで移る。1回で無効になり、期限は付けない。控えておけば、端末を失くしても戻れる
- 新しい端末では、トップの「引き継ぎコードをお持ちの方」からコードを入れる。デモや普段の画面の邪魔にならないよう、トップは小さな文字のリンクにし、発行するボタンは拠点の一番下に畳む。別の端末で拠点のURLを開いたときも、トップページへ移す
- 悪い点: コードを控えずに Cookie を消すと戻れない。iPhone のホーム画面アプリは別の端末として扱われることがあり、最初に一度コードの入力が要る
- この仕組みを入れる前のユーザーは、最初に開いた端末に結びつける
- Googleログイン（Firebase Authentication）は、コンソールの設定と権限の追加が要り、iPhone のホーム画面アプリで動かないおそれがあり、全員にログインを強いるので見送った
- 公園の距離を丸める案は、試算で効果がなかった。家の座標が約100m単位の格子にあるので、250m単位に丸めても、公園が数件あれば、ほぼ1マスに絞れた。公園の一覧は家の周りを探す仕組みなので、一覧を読まれたら近所は分かる。読めないようにするしかない

## シェルターの候補の出し方（捨てた案: 公園を近い順に出すだけ）

- 公園検索は1回で20件までなので、公園の多い地域では近い順の20件で埋まり、拠点ランクを上げても遠くの公園が出てこなかった
- 20件に届いたときだけ、人気順でも検索して範囲全体から集める。1回の表示で検索が2回になるので、結果は10分キャッシュする
- 探索半径の2割より近い公園どうしは1つにまとめる（地図のピンが重ならない程度）。最大12件を、近くから遠くまで偏らないように出す

## 安全とプライバシーの設計

- 家と最後の位置は丸めて保存し、座標そのものは画面とAPIに渡さない。拠点の画面は地図を使わない
- 運営は Firestore で丸めた家の位置（誤差は最大約70m）を見られる。位置で判定するゲームなので割り切った
- 現在地はURLに載せず、本文で送る。URLに載せると Cloud Run のリクエストのログに残るため
- 家の周りを画面に一切映さない、とまではしない。外に出れば逃走中の地図に自分の位置が出るし、家でフリーランを始めればそこが映る。守るのは「家の座標を画面とAPIに渡さない」「外に出る前の画面に家（今いる場所）の印を出さない」の2つ
- 公園選び（予約とフリーラン）では、候補の公園だけを地図に出す。家や今いる場所の印は出さず、地図の範囲も公園だけに合わせる。公園の場所が名前だけでは分かりにくかったため。短い住所も一覧に出す。地図のピンを押しても選べる
- ログインはない。代わりに端末に結びつける（下の「端末に結びつける」の節）。トップページの「続きから」のため、開いた拠点のユーザーIDをブラウザに覚えさせる
- ただし、追跡中の最後の位置だけは約7m単位（小数第4位）で保存する。約70m単位だと、ゾンビが本人から数十m離れた点で止まって捕獲され、画面の動きと判定がずれたため。家の位置は約70m単位のまま
- 家へ近づいている間のゾンビの座標は、APIに出さない。2回取るだけで、向かう先（家）が約30mの精度で分かったため。追跡が始まるときも、家のほぼ真上にいるゾンビをそのまま見せず、距離を保ったまま背後の左右にずらして置き直す
- 追跡中のゾンビの位置と進む方向から、最後の位置は推測できる。本人の端末でだけ見られる前提
- 閉じている間は位置を取得しない。通知の文面に位置を入れない
- Referrer-Policy を strict-origin にして、URLのIDを外部へ送らない（no-referrer は Maps のキー制限と衝突する）
- 脱出、捕獲、歩いた距離の判定はサーバーで行う
- 逃走中の地図に時間切れの失敗を作らず、走って急ぐ圧力を下げる
- 暗い時間帯は注意を表示する
- APIキーは Secret Manager に置き、リポジトリには入れない
- 本番で開発用データが動くとデモの偽装になるため、設定が欠けていれば起動を止める
