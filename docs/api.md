# APIとデータの約束

画面からこのAPIを呼んで、アプリを作っています。形式を変えるときは、ここを先に更新します。

この文書では、画面を次の番号で呼びます。

| 番号 | 画面 | URL |
|---|---|---|
| ① | トップ | `/` |
| ② | 隊員登録 | `/setup` |
| ③ | 拠点 | `/home/{user_id}` |
| ④ | シェルター選び（毎日の逃走の予約） | `/reserve/{user_id}` |
| ⑤ | ゾンビ接近中（カウントダウンと「脱出！」ボタン） | `/escape` |
| ⑥ | 逃走中の地図（脱出した後の3Dの地図） | `/escape` |
| ⑦ | クリア／ゲームオーバー | `/escape` |

フリーランの公園選び（`/run/{user_id}`）には番号を付けていません。

動かしたまま `http://localhost:8000/docs` を開くと、全APIの詳しい形式を確認して試せます。

## 共通

- IDは推測できない長い文字列です
- 拠点とミッションのAPIと画面は、登録した端末でだけ使えます（HttpOnly の Cookie `dh_device`）。他の端末からは403（`other_device`）で、画面はトップページへ移ります（トップの「引き継ぎコードをお持ちの方」からコードの入力へ進めます）。同じオリジンの `fetch` なら Cookie は自動で付きます
- 家の座標はどのAPIでも返しません。ゾンビの座標も、追跡中だけ返します。脱出の判定もサーバーで行います
- エラーは `{"error": {"code": "...", "message": "画面に出せる日本語"}}` で返ります
- 時刻はタイムゾーン付きのISO 8601です（JavaScriptなら `new Date(...).toISOString()`）
- 使いすぎると429（`too_many_requests`）が返ります。ユーザー作成はIPごとに1時間10回、公園の検索と徒歩ルートは1人1日100回までです

## 画面が使うAPI

### ② 初期設定: `POST /api/users`

```json
{"nickname": "隊員", "lat": 35.681, "lng": 139.767, "daily_notify_time": "18:00"}
```

座標はサーバーが丸めて保存します。登録のときのゾンビは、ノーマルの速さ（時速6km）でちょうど時刻に着く距離に出ます（400m〜5km）。毎日の時刻まで4分を切っていたら、400m先に出て4分後に着き、2回目からは毎日の時刻に来ます。

応答の `user.home_url` へ移動してください。

### 拠点: `GET /api/users/{user_id}`

家が「拠点」です。拠点ポイント（逃げた距離＋ボーナス）の累計で拠点が豪華になり、捕まると振り出し（テント）に戻ります。主な項目は次のとおりです。

| 項目 | 内容 |
|---|---|
| `base_rank`, `base_rank_name` | 拠点のランク（1〜10）と名前（テント、小屋、バリケードの家、見張り台つきの砦、要塞、二重壁の要塞、発電所つきの要塞、監視塔の要塞、菜園つきの城塞、灯台の城塞都市） |
| `base_escaped_m` | ランクを決める拠点ポイントの累計（逃げた距離、ハードの上乗せ、資材）。捕まると0 |
| `next_rank_m` | 次のランクに必要な累計距離。最大ランクなら `null` |
| `lost_base_rank`, `lost_base_rank_name` | 捕まって崩れたランク。次にクリアするまで崩壊の演出に使う |
| `total_walked_m` | 減らない生涯の歩いた距離（ボーナスは含めない） |
| `freeze_count` | ためているフリーズの数（最大3） |
| `zombies` | ゾンビ全員の `lat`, `lng`, `km`。ハードの追跡中は3体。`zombie_lat`, `zombie_lng`, `zombie_km` は最も近い1体。家へ近づいている間は座標が `null` で、`km` だけ入る |
| `chase_mode` | 追跡中のモード（`normal` / `hard`）。家へ近づいている間は `null` |

経験値とレベルは廃止しました。シェルターの探索範囲は拠点ランクで広がります。

振り出しに戻るのは「捕まったとき」です。毎日の時刻までに脱出しなかった場合（予約していても同じ）、追いつかれた場合が該当します。

### 別の端末で続ける

`POST /api/users/{user_id}/transfer-code` で引き継ぎコードを発行します（応答は `{"code": "ABCD-EFGH-JKMN"}`）。1回使うか、発行し直すと無効になります。期限はありません。

新しい端末では `POST /api/devices/link` に `{"code": "..."}` を送ります。応答の `home_url` へ移動してください。間違えると404（`bad_code`）、IPごとに1時間10回までです。

### 毎日の時刻: `PUT /api/users/{user_id}/daily-time`

ゾンビは毎日同じ時刻に来ます。習慣にするため、予約（④）では時刻を変えられません。この API で毎日の時刻を変えると、**翌日から**反映されます。

```json
{"daily_notify_time": "07:30"}
```

- 今日の到着がまだなら、今日はもとの時刻のまま。直前に変えて逃れることはできない
- 今日の分がもう終わっているなら、明日の到着が新しい時刻に動く（予約していればミッションも動く）
- 1日に2回来ることはない

応答は `GET /api/users/{user_id}` と同じ形です。

### フリーズを使う: `POST /api/users/{user_id}/freeze`

本文はありません。フリーズを1つ使い、次の毎日の時刻にゾンビが来ないようにします（その次の日の時刻に来ます）。

- ゾンビは5km先に出直す
- 次の時刻に向けて予約していれば、ミッションもその次の日に移る
- 休んだ日は連続日数を切らない（数も増えない）
- フリーズがないと409（`no_freeze`）、追跡中は409（`chasing`）、逃走中のミッションがあると409（`already_running`）

応答は `GET /api/users/{user_id}` と同じ形です。

### フリーラン: `POST /api/users/{user_id}/runs`

毎日の時刻とは別に、いつでも何回でも走れます。画面は `/run/{user_id}` です。まず今いる場所の近くの公園を取ります。

`POST /api/users/{user_id}/shelters/near`（座標がログに残らないよう、URLではなく本文で送ります）

```json
{"lat": 35.69, "lng": 139.77}
```

選んだ公園で走り始めます。

```json
{"place_id": "公園のID", "mode": "normal", "lat": 35.69, "lng": 139.77}
```

- 応答はミッション（`kind` が `free`、`status` が `escaped`）。そのまま `escape_url`（⑥）へ移る
- ゾンビは背後400m（シェルターと反対側）に出る。ハードはさらに2体が、本体の左右少し後ろに群れで出る
- 位置の精度は問わない（PCでも入れる）。歩いた距離とアイテムは、精度の良い位置でだけ数える
- 毎日の時刻より前に捕まっても、拠点は崩壊せず、連続日数も残る（`last_result` が `run_captured`）。その回のポイントが入らないだけ
- 毎日の時刻を過ぎてから捕まると、毎日のゾンビに捕まったのと同じく拠点は崩壊する（`last_result` は `captured`）
- 毎日の時刻より前に終わると（クリアでも捕獲でも）、毎日のゾンビの距離は戻らず、走っていた時間の分も進んだ位置から続きを近づく。毎日の時刻をまたいで終わると、5km先に出直して翌日の時刻に来る
- 毎日の時刻のゾンビはフリーランをしても来る。ただし毎日の時刻をまたいで走り、シェルターまで逃げ切れば、予約していた毎日のミッションは達成扱い（`result.covered_by_free_run` が `true`、距離0）。走っている間は達成にも失敗にもならない
- 追跡中は409（`chasing`）、逃走中のミッションがあると409（`already_running`）

### アバター: `PUT /api/users/{user_id}/avatar`

```json
{"outfit": "orange", "skin": "tan"}
```

服は `lime`, `orange`, `blue`, `red`, `violet`, `white`、肌は `light`, `fair`, `tan`, `brown`, `dark`。それ以外は422です。`GET /api/users/{user_id}` の `avatar_outfit`, `avatar_skin` で今の色が分かります。

### 成果: `GET /api/users/{user_id}/stats`

合計距離（`total_walked_m`）、直近7日の距離（`week_walked_m`、日本時間）、クリア回数、捕まった回数、連続日数、今と最高の拠点ランク、直近10回の記録（`history`: `cleared_at`, `shelter_name`, `walked_m`）を返します。画面は `/results/{user_id}` です。

### 外のマップと現在地: `POST /api/users/{user_id}/position`

地図は `static/map.js` を共通で使えます。⑥では追従モードにします。

```javascript
const map = ZombieMap.create(document.getElementById("map"), { key: mapsKey, mapId: mapId });
map.update({ zombie: {lat, lng}, player: {lat, lng}, shelter: {lat, lng} });
map.setFollow(true);       // 自分を中心に傾けて表示する。1本指で回す・傾ける、2本指で拡大・回転（追従は止まらない）
map.toggleTopView();       // 真上 ⇄ 斜め。真上になったら true
map.setEdgeInsets({ top: 150, bottom: 160 });  // 画面外のゾンビの矢印を、HUD に重ならない範囲に置く
map.onFollowChange((following) => { /* 止まったら「現在地に戻る」を出す */ });
```

カメラは歩く向きでは自動で回りません（`setHeading` は互換のために残した何もしない関数です）。画面の外にいるゾンビは、画面の端に方角と距離の矢印で表示されます。

⑥を開いている間は15秒に1回くらい現在地を送ってください。閉じている間は送りません。拠点の画面は家の座標を扱わないので、地図も現在地も使いません。応答の `zombie_lat`, `zombie_lng`, `zombie_km` で地図を更新します。

ゾンビは `arrival_at`（毎日の時刻）にちょうど家へ着きます。その時刻までに追跡が始まっていなければゲームオーバーです。追跡は、脱出（⑤）を押すか、シェルターを選んだあとに家から200m以上離れた位置が届くと始まり（`chasing` が `true`）、ゾンビは最後の位置を追います。速さはモードで決まります（ノーマル：1体・時速6km、ハード：3体・時速9km）。`user_id` は `home_url` の末尾です。

```json
{"lat": 35.69, "lng": 139.77, "accuracy_m": 15}
```

ブラウザは画面を消すと位置を取得できません。追跡中に位置が45秒より長く届かないと、ゾンビが最後の位置に着いても捕獲せず、次の位置を待ちます。位置が戻ったら、ゾンビは最後の位置を通って今の位置へ追い続けていたものとして計算し、追いつかれていれば捕獲します。60分届かなければ、放置したものとして捕獲します。

ゾンビの目標の座標は応答に含まれません。走っている間に画面を見させないよう、演出は音声や振動を中心にしてください。

### ⑤ ミッションの取得: `GET /api/missions/{id}`

`/escape?mission={id}` のURLからIDを取り出して呼びます。主な項目は次のとおりです。

| 項目 | 内容 |
|---|---|
| `status` | `reserved` / `escaped` / `cleared` / `failed` |
| `depart_at` | ゾンビが家に着く時刻。これが脱出の期限で、カウントダウンに使う |
| `shelter` | `name`, `lat`, `lng`, `distance_m`, `checkin_radius_m`, `direction`, `kind`（`park`：公園、`landmark`：公園がないときのコンビニや駅など、`waypoint`：それもないときの地図上の目印） |
| `kind` | `daily`（毎日の時刻）/ `free`（フリーラン） |
| `mode` | `normal` / `hard` |
| `items` | 脱出したときに道のりに置かれるアイテム。`id`, `kind`（`material`。前に作ったミッションには、やめた `repel` が残っていることがある）, `lat`, `lng`, `collected` |
| `material_bonus_m` | 拾った資材のボーナス |
| `home_url` | 拠点へ戻るリンク |
| `result` | クリア後の結果 |

Geminiの物語と音声は廃止しました（`story`, `audio_url` はありません）。

### ④ 予約: `POST /api/users/{user_id}/missions`

```json
{"place_id": "シェルターのID", "mode": "hard"}
```

時刻は送りません（送っても無視します）。次に来る毎日の時刻に向けた予約になり、`depart_at` はその時刻です。`mode` は省略するとノーマルです。追跡中は409（`chasing`）、予約中や逃走中のミッションがあると409（`already_reserved`）です。シェルターの一覧は `GET /api/users/{user_id}/shelters` で取れます。

### ⑤ 脱出: `POST /api/missions/{id}/escape`

```json
{"lat": 35.69, "lng": 139.77, "accuracy_m": 15}
```

`accuracy_m` はブラウザの `coords.accuracy` です。HTTPステータスは200で、`status` を見て画面を分けます。

| `status` | 画面の動き |
|---|---|
| `escaped` | ⑥へ進む。`shelter_changed` が `true` なら、外出先なのでシェルターを今いる場所の近くに替えた（ミッションを取り直すと新しいシェルターが入っている） |
| `too_early` | 出発10分前より早い |
| `timeout` | ゲームオーバー。`home_url` と「明日リベンジ」を出す。`depart_at` までに脱出しないとこの状態になる |
| `low_accuracy` | 精度が100mより悪い。屋外でやり直してもらう |

家にいても脱出できます（フリーランと同じく、押した瞬間に追跡が始まり、家にとどまれば追いつかれます）。家から1.5km以上離れた所で脱出し、予約したシェルターが今いる場所から選べる範囲より遠いときは、今いる場所の近くで、予約したときの距離にいちばん近いシェルターに替えます。見つからないときや検索に失敗したときは、予約したままです。フリーラン中は409（`already_running`）です。

位置情報の許可がないときはAPIを呼ばず、画面側で案内してください。

### ⑥ アイテムを拾う: `POST /api/missions/{id}/items/{item_id}/collect`

脱出すると、脱出した地点からシェルターまでの直線上に、資材（`material`）が約300mおきに置かれます（1〜3個。家から200m以内には置きません）。毎日の逃走では、2〜3回に1回、道のりの途中にフリーズ（`freeze`）も1個置かれます。画面は、今の位置から40m以内に入った未回収のアイテムについて、現在地を送ります。画面を見なくても分かるよう、拾えたら振動で知らせてください。

```json
{"lat": 35.69, "lng": 139.77, "accuracy_m": 15}
```

| `status` | 意味 |
|---|---|
| `collected` | 拾えた。`kind` と、拾った後の最も近いゾンビまでの距離 `zombie_km` が入る |
| `already` | もう拾っている |
| `too_far` | 40mより遠い。`remaining_m` が入る |
| `low_accuracy` | 精度が50mより悪い |

- 資材：拠点ポイント+200。シェルターに着いたときに入る（途中で捕まると失う）
- フリーズ：シェルターに着いたときに1つたまる（最大3。途中で捕まると失う）。ミッションの `freeze_found` が `true` になる

逃走中（`escaped`）以外は409です。

### ⑥ 徒歩ルート: `POST /api/missions/{id}/route`

```json
{"lat": 35.69, "lng": 139.77}
```

脱出後だけ使えます。脱出前は409（`not_escaped`）です。応答は `points`（`lat`, `lng` の一覧）、`distance_m`、`duration_min` です。Routes API の費用がかかるので、⑥を開いたときと「ルートを更新」を押したときだけ呼びます。

### ⑥ チェックイン: `POST /api/missions/{id}/checkin`

送る内容は脱出と同じで、加えて画面で数えた道のり `walked_m`（任意、メートル）を送ります。

```json
{"lat": 35.69, "lng": 139.77, "accuracy_m": 15, "walked_m": 1240}
```

`walked_m` は、精度が30m以内の位置どうしの距離を足し、時速15kmを超える区間を除いて数えます。サーバーは、シェルターまでの直線距離を下限、「出発10分前から時速15kmで歩き続けた距離」を上限として計上します。送らなければ直線距離になります。

着いたとみなすのは、シェルターの中心から `shelter.checkin_radius_m` 以内です。公園の大きさで50〜100m、大きさが分からない施設と地図上の目印は80mです。上限が200mだったころに予約したシェルターも、100mとして返します。画面のチェックインのボタンは、この範囲に入っているときだけ出します。

| `status` | 画面の動き |
|---|---|
| `cleared` | ⑦へ進む。`result` に結果が入る |
| `too_far` | `remaining_m` を使って「あと〇〇m！」 |
| `low_accuracy` | 精度が50mより悪い（脱出の100mより厳しい）。屋外でやり直してもらう |
| `captured` | 画面を消している間に追いつかれていた。ミッションを取り直して失敗の画面を出す |

脱出前に呼ぶと409（`not_escaped`）が返ります。連打しても距離は1回分だけです。⑥に時間切れの失敗はありませんが、シェルターに着く前に追いつかれるとミッションは `failed` になり、チェックインは409になります。

### ⑦ クリア結果: `result` の中身

| 項目 | 内容 |
|---|---|
| `walked_m` | 今回計上した歩いた距離 |
| `mode`, `mode_bonus_m` | モードと、ハードの上乗せ（歩いた距離の0.5倍） |
| `material_bonus_m` | 資材のボーナス |
| `freeze_gained` | フリーズが1つたまったか（上限のときは `false`） |
| `base_points_gained` | 拠点ポイントに入った合計（歩いた距離＋ハードの上乗せ＋資材） |
| `base_rank_before`, `base_rank_after` | 違っていれば拠点の強化演出 |
| `base_rank_name_after`, `base_escaped_m_after` | クリア後の拠点の名前と拠点ポイントの累計 |
| `streak` | 連続日数 |

毎日のミッションをクリアするとゾンビは5km先に出直し、翌日の時刻へ向けて拠点に近づき始めます。フリーランのクリアでは出直さず、続きから近づきます。

## 画面の置き場所

- HTMLは `templates/`、CSSとJavaScriptは `static/` に置きます
- 画面の登録は `routes/pages.py` です。⑤⑥⑦は `/escape` の1画面で、ミッションの状態に応じて切り替えます
- `services/location.py` の距離計算はBの処理でも使っています。改良する場合は関数名を保ってください
